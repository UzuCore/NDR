# NDR r197 — 긴 파일명 툴팁의 글자 누락·화면 깨짐 수정

검수일: 2026-11-01 / 대상: NDR Rust Windows x64 / r196 기준

## 증상과 직접 확인

- 사용자 제보: 긴 파일명에 포커스를 두면 잠깐 나타나는 툴팁에 글자가 보이지 않거나 창 레이아웃이 깨진다. 약 3초 후 사라지므로 실시간 검수가 필요하다.
- 실제 실행 중인 사용자 NDR은 `D:\2026-10-29\NDR.exe`이며, 별도 프로세스로 실행되는 r196 배포본을 사용해 **동일 Black 테마와 Auto/2분할 화면**으로 테스트했다.
- 격리 폴더 `target/tooltip-r197-qa/fixture-left`에 224자짜리 긴 파일명을 만들고 NDR 프로세스를 별도 실행해 선택했다. NDR 자체를 포함한 실제 데스크톱 프레임은 `target/tooltip-r197-qa/clicked-at-0950.png`, `keyboard-at-0750.png` 등에 보존했다. 자동 입력 실험에서는 파일명 선택 및 잘린 표시를 재현했지만, 포커스 조건 때문에 매번 일시적 툴팁을 캡처하지는 못했다. 따라서 툴팁을 확정적으로 표시하는 **전용 렌더링 스냅샷**과 검사 코드를 추가했다.

## 코드에서 확인된 고장 경로

1. `src/ui/panes.rs::original_name_tip`: 일반 목록 툴팁의 너비를 `full.size().x + 10`으로 계산했다. 파일명 200자 이상이면 좌우 패널/메인 창/모니터보다 커질 수 있다.
2. 사각형이 창을 벗어나면 `show_tip_window`가 **별도 egui 네이티브 Viewport**를 만들었다. 모니터보다 큰 크기와 원본 레이아웃에서 가져온 Galley가 결합하면 별도 창의 글자가 클리핑되거나 아예 화면 밖으로 나갈 수 있다. 클리핑된 UI만 표시하는 정상 본창과 별도로 팝업 창이 만들어진 것이 화면이 깨진 것처럼 보이는 한 원인이 된다.
3. 썸네일 툴팁은 `word_break_lines`를 사용했는데, 공백 없는 긴 파일명은 하나의 '단어'로 간주되어 폭을 초과해도 줄바꿈하지 않았다.
4. 원본 목록에서 생성된 Galley를 그대로 밝은 `COLOR_INFOBK` 배경에 그렸다. Galley의 색상 설정이 목록의 색상을 보존한다면 `painter.galley(..., fallback_color)`로는 실제 텍스트 색상이 바뀌지 않아 글자가 배경과 섞일 수 있었다.

## 적용한 수정

- `bounded_name_tip_layout`은 기존 팝업 대신 **현재 NDR 메인 화면 범위 안에만** 사각형을 만든다. 앵커가 화면 가장자리/하단에 있어도 사각형을 안쪽으로 이동한다.
- 한 줄에 들어가지 않는 글자는 **UTF-8/한글 및 공백 없는 파일명을 포함해 문자 단위로 줄바꿈**한다. 기본 텍스트 최대 너비를 740pt로 제한하고 현재 창 크기에 따라 더 줄인다. 화면 높이 제한 내에서 가능한 최대 줄을 표시한다.
- 툴팁 글자는 별도 새 Galley를 `COLOR_INFOTEXT`로 생성하므로 사용자의 테마나 선택 강조색과 상관없이 툴팁 배경 위에 그려진다. 사용자 목록용 밑줄/취소선 스타일은 유지한다.
- Auto/Names/Details와 Thumbnails의 툴팁을 동일한 안전한 렌더러로 통합한다. `show_tip_window`는 과거 팝업 진단 경로에만 남아 있으며 실제 파일명 툴팁에서는 사용하지 않는다.
- 기존의 표시 지연 600ms, 3초간 보여준 뒤 자동으로 숨기기 동작은 변경하지 않았다.

## 검수 시나리오

- `very_long_name_tooltip_wraps_all_characters_inside_viewport_with_readable_color`: 200자 이상 영문/한글 파일명을 470×260, 1400×850 창 오른쪽 아래에 배치해 **전체 원문/전경색/줄바꿈/경계 내 표시**를 검사한다.
- `selected_long_filename_tooltip_is_bounded_in_auto_names_details_and_thumbnails`: 실제 긴 이름의 테스트 파일을 만들어 Auto, Names, Details, Thumbnails 네 종류의 목록에서 포커스를 두고 600ms 경과 상태로 프레임을 그린다. 툴팁은 창 밖으로 나가면 안 된다.
- `--shot longnametip`: 실제 GUI의 스냅샷 프레임에서 200자 이상 파일명을 하단 우측에 그린 뒤 PNG로 저장한다. 자동 테스트만으로는 놓칠 수 있는 배경·글자·크기·클리핑을 이미지로 검수하기 위한 전용 렌더링 샘플이다.
- **실제 렌더링 결과 PASS:** `target/tooltip-r197-qa/long-name-tooltip-r197-render.png` (1400×850, 145,113바이트). 표시 좌표는 `x=648.625, y=769, w=743.375, h=73`이고 끝점 `right=1392, bottom=842`로 화면에 안전하게 들어왔다. 실제 PNG를 열어 검수한 결과 영문·한글 혼합 긴 파일명이 밝은 배경에 검은색으로 3줄에 걸쳐 출력되었고 마지막 `.txt`까지 보였다. 실사용 창을 가리지 않은 상태로 검수 프레임을 캡처했으며 `foreground=false`였다.
- 기존 압축파일, 폴더 아이콘, 파일 작업 및 버튼/단축키 회귀 테스트를 유지한다.

## 데이터 보호

기존 사용자 NDR 프로세스 `D:\2026-10-29\NDR.exe`는 종료하거나 덮어쓰지 않는다. 실험용 NDR은 `--profile`이 지정된 별도 폴더와 프로젝트의 격리 테스트 파일만 사용했다. 모든 출력 및 캡처는 Git 추적 제외 폴더 `target/tooltip-r197-qa`에 둔다.

이 보고서는 위의 증상 및 선택한 UI 경로를 대상으로 한 검수다. NDR 모든 UI/기기/OS 설정을 전수 테스트했다는 의미는 아니다.
